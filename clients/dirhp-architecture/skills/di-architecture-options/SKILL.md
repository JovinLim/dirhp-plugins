# Architectural alternatives

Use the base DI connection and options skill. Fetch `options-and-snapshots` for branching, staging,
comparison, and restore contracts. Use `di-architecture-evaluation` for geometric criteria.

## Make the comparison meaningful

Identify the baseline and decision criteria from the brief. For a requested new direction, fork
the intended saved state so the source stays available. Name the option with the user's label and
a factual strategy, such as “B — Narrow courtyard massing.” Do not claim an unmeasured benefit in
its name or description.

Keep context consistent: site boundaries, external references, programme basis, frames, and included
geometry. If these differ, report that difference before attributing results to the design strategy.
Side-by-side document placement is presentation; compare normalized design geometry or a common
datum so the display offset does not become a design difference.

Use `di_compare_design_states` for the geometric and semantic change census, then inspect only the
changes relevant to the brief. Match comparable systems through authored scope and source ownership;
do not assume separately created alternatives share object IDs. A change count alone is not a
performance comparison.

## Explain trade-offs

Measure the same criteria with the same representation and method in each option. Report targets,
results, and unresolved cases. Separate geometric evidence from visual judgments such as proportion
or articulation. Do not invent weights for a combined score; use the designer's priorities or show
the trade-offs directly.

Use consistent views when visual comparison helps. Viewport capture is a separate review action,
not a prerequisite or proof for saving. An unsaved alternative can be reviewed as staging without
creating history just for inspection.

## Handoff

State the options and design states compared, the decision supported, and any outstanding evidence.
If the user selects a direction, save within existing authorization and record a short factual
note. A study-only request ends with the comparison. Do not delete the other alternatives.

For “restore” or “revert,” distinguish an exact saved artifact from a design regenerated with
current inputs. Use the base guide's targeted restore and occurrence ownership rules.

Read [the massing example](references/massing-comparison.md) when planning a study with several
criteria. It illustrates decisions; it does not require a fixed set of options or metrics.
